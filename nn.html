Concept 01

The neuron and its activation function

A neuron takes inputs x, forms a weighted sum plus a bias, and passes it through a nonlinear activation:

z = w₁x₁ + w₂x₂ + … + b = w·x + b a = f(z)

Without the nonlinearity, any stack of layers collapses into one linear map. The activation is what lets depth add power. A layer is many neurons sharing the same inputs, written as a matrix product a = f(W x + b), and a network chains layers.

The choice of activation affects how gradients flow. Compare the functions below and look at their derivatives, because that is what backpropagation multiplies by.

Python · the same functions in PyTorch
import torch, torch.nn.functional as F

x = torch.linspace(-5, 5, 11, requires_grad=True)
for name, fn in [("relu", F.relu), ("sigmoid", torch.sigmoid), ("tanh", torch.tanh),
                 ("gelu", F.gelu), ("silu", F.silu)]:
    y = fn(x)
    y.sum().backward()               # gradient of each output w.r.t. its own x
    print(name, x.grad.detach().numpy().round(2))
    x.grad = None

Learner tips

  • Default to ReLU (or GELU / SiLU in transformers) in hidden layers. Use sigmoid only for a binary output and softmax for multi-class outputs.
  • Sigmoid and tanh saturate: their slope is near zero for large |x|. Stacked deep, gradients shrink toward nothing.
  • A ReLU neuron whose input is always negative outputs zero and gets zero gradient. That "dead ReLU" problem is why Leaky ReLU exists.

Industry now

  • Sigmoid and tanh survive mainly as gates and output layers. Hidden layers in modern transformers use GELU or gated variants such as SwiGLU. CNNs still use ReLU or SiLU.
Concept 02

Softmax, cross-entropy and what "loss" means

The network's last layer produces raw scores called logits. Softmax turns them into probabilities that sum to one, and cross-entropy measures how much probability went to the right answer:

softmax(z)ᵢ = e^(zᵢ/T) / Σⱼ e^(zⱼ/T) loss = −log( p_correct )

T is a temperature. Low T sharpens the distribution toward the biggest logit; high T flattens it. The same knob appears again when sampling from language models. Cross-entropy is small when the model is confident and right, and grows without bound when it is confident and wrong.

Python · a numerically stable softmax
import numpy as np

def softmax(z, T=1.0):
    z = np.asarray(z) / T
    z = z - z.max()                 # subtract the max so exp() cannot overflow
    e = np.exp(z)
    return e / e.sum()

def cross_entropy(logits, target):
    # log-softmax computed directly is safer than log(softmax(...))
    z = logits - logits.max()
    logp = z - np.log(np.exp(z).sum())
    return -logp[target]

print(softmax([2, 1, 0, -1]), cross_entropy(np.array([2., 1., 0., -1.]), 0))

Common traps

  • In PyTorch, nn.CrossEntropyLoss expects raw logits. Applying softmax yourself first is a classic bug that silently hurts training.
  • For regression use MSE or Huber loss. For binary classification use BCEWithLogitsLoss, which is more stable than sigmoid followed by BCE.
Concept 03

Backpropagation, step by step

Training needs the gradient of the loss with respect to every weight. Backpropagation computes all of them in one backward sweep using the chain rule: the gradient at a node is the gradient arriving from above times the node's local derivative.

z = w₁x₁ + w₂x₂ + b a = σ(z) L = (a − y)² ∂L/∂a = 2(a − y) ∂a/∂z = a(1 − a) ∂L/∂z = ∂L/∂a · ∂a/∂z ∂L/∂w₁ = ∂L/∂z · x₁ ∂L/∂b = ∂L/∂z

Frameworks such as PyTorch record these operations as they run (autograd), so loss.backward() does the sweep for you. Doing one by hand is the best way to understand it.

import torch

x1, x2 = torch.tensor(1.0), torch.tensor(-0.5)
w1 = torch.tensor(0.8, requires_grad=True)
w2 = torch.tensor(-0.4, requires_grad=True)
b  = torch.tensor(0.1, requires_grad=True)
y  = torch.tensor(1.0)

a = torch.sigmoid(w1 * x1 + w2 * x2 + b)
loss = (a - y) ** 2
loss.backward()
print(w1.grad.item(), w2.grad.item(), b.grad.item())   # matches the table above

Learner tips

  • Cost of backward is roughly twice the forward pass, and it needs the forward activations kept in memory. That memory is why training uses far more GPU memory than inference.
  • When a custom layer misbehaves, compare its gradient with torch.autograd.gradcheck, the numerical check shown in the demo.
  • Gradients are accumulated by default in PyTorch. Call optimizer.zero_grad() every step.

Python · the same model in PyTorch
import torch, torch.nn as nn
from sklearn.datasets import make_moons

X, y = make_moons(400, noise=0.15, random_state=0)
X = torch.tensor(X, dtype=torch.float32)
y = torch.tensor(y, dtype=torch.float32).unsqueeze(1)

model = nn.Sequential(nn.Linear(2, 6), nn.Tanh(), nn.Linear(6, 4), nn.Tanh(), nn.Linear(4, 1))
opt = torch.optim.Adam(model.parameters(), lr=0.03)
loss_fn = nn.BCEWithLogitsLoss()

for epoch in range(300):
    for i in torch.randperm(len(X)).split(32):      # minibatches
        opt.zero_grad()
        loss = loss_fn(model(X[i]), y[i])
        loss.backward()
        opt.step()
acc = ((model(X) > 0).float() == y).float().mean()
print(float(acc))
Concept 05

Optimisers on a 3D loss landscape

The loss is a surface over the weights, and an optimiser decides how to walk downhill. Plain SGD follows the local slope. Momentum keeps a running velocity, which smooths zigzags in narrow valleys. RMSProp and Adam scale each step per parameter by recent gradient size.

SGD: w ← w − lr · g Momentum: v ← β·v + g w ← w − lr · v RMSProp: s ← ρ·s + (1−ρ)·g² w ← w − lr · g / (√s + ε) Adam: m ← β₁m + (1−β₁)g s ← β₂s + (1−β₂)g² w ← w − lr · m̂ / (√ŝ + ε) (m̂, ŝ bias-corrected)

Python · the update rules written by hand
import numpy as np

def adam(grad_fn, w, lr=0.1, b1=0.9, b2=0.999, eps=1e-8, steps=200):
    m = np.zeros_like(w); s = np.zeros_like(w)
    for t in range(1, steps + 1):
        g = grad_fn(w)
        m = b1 * m + (1 - b1) * g
        s = b2 * s + (1 - b2) * g * g
        m_hat = m / (1 - b1 ** t)          # bias correction for the early steps
        s_hat = s / (1 - b2 ** t)
        w = w - lr * m_hat / (np.sqrt(s_hat) + eps)
    return w

print(adam(lambda w: np.array([0.5 * w[0], 3 * w[1]]), np.array([-2.0, 1.2])))

Learner tips

  • Adam (or AdamW) with lr around 1e-3 is the standard first choice. SGD with momentum often generalises slightly better for vision models when tuned well.
  • Learning rate matters more than the choice of optimiser. Sweep it on a log scale (1e-4, 3e-4, 1e-3, 3e-3).
  • Use AdamW, which applies weight decay separately, instead of Adam with an L2 term.
Concept 06

Initialisation and signal flow

If weights start too small, the signal shrinks layer by layer until it vanishes. If they start too large, it explodes. Good initialisation keeps the variance of activations roughly constant with depth:

Xavier / Glorot (tanh, sigmoid): Var(w) = 1 / n_in He / Kaiming (ReLU): Var(w) = 2 / n_in

The factor of two for ReLU compensates for it zeroing half of its inputs.

Concept 07

Regularisation and the learning rate schedule

Dropout randomly switches off a fraction p of neurons on every training step and rescales the rest by 1/(1−p), so the network cannot lean on any single unit. At inference every neuron is used. Other regularisers include weight decay, data augmentation and early stopping.

The learning-rate schedule changes the step size during training. Warmup avoids early instability, and decaying toward zero lets training settle into a minimum.

Concept 08

Small but important concepts

The details that separate a network that trains from one that quietly fails.

Batch normalisation

Normalise each feature over the batch, then rescale with learned γ and β. Speeds up and stabilises training of CNNs.

x̂ = (x − μ_B) / √(σ²_B + ε); y = γ·x̂ + β
nn.BatchNorm2d(64)

Layer normalisation

Normalise across the features of each example. Independent of batch size, so it is standard in transformers.

x̂ = (x − μ) / √(σ² + ε) over features
nn.LayerNorm(512)

Residual connection

Add the input to the layer's output so gradients have a direct path. This is what makes very deep networks trainable.

y = x + F(x)
out = x + block(x)

Gradient clipping

Rescale gradients whose norm is too large. Standard for RNNs and transformers.

g ← g · min(1, c / ‖g‖)
clip_grad_norm_(model.parameters(), 1.0)

Label smoothing

Train toward 0.9 instead of 1.0 for the correct class. Reduces over-confidence.

y_smooth = (1 − ε)·y + ε / K
CrossEntropyLoss(label_smoothing=0.1)

Mixed precision

Run most maths in 16-bit floats for speed and memory, keeping a 32-bit master copy of the weights.

loss scaling avoids underflow
with torch.autocast("cuda", dtype=torch.bfloat16):

Batch size and epochs

One epoch is a pass over all data. Larger batches give smoother gradients but fewer updates per epoch.

steps per epoch = N / batch_size
DataLoader(ds, batch_size=64, shuffle=True)

Weight decay

Shrinks weights a little every step, which discourages large weights. Use AdamW so the decay is decoupled.

w ← w − lr·(g + λ·w)
AdamW(params, weight_decay=0.01)

Early stopping

Stop when validation loss stops improving, and keep the best checkpoint.

stop if no gain for k epochs
best_state = copy.deepcopy(model.state_dict())

Vanishing and exploding gradients

Products of many small (or large) derivatives shrink (or blow up) toward the early layers. Fixes: ReLU, good init, normalisation, residuals, clipping.

∂L/∂w₁ = Π (layer derivatives)
print(p.grad.norm()) for p in model.parameters()

Log-sum-exp trick

Compute log(Σ e^z) stably by pulling out the maximum. Frameworks do this inside cross-entropy.

log Σ e^zᵢ = m + log Σ e^(zᵢ−m)
torch.logsumexp(z, dim=-1)

Transfer learning

Start from a pretrained network and fine-tune, often with a smaller learning rate on the pretrained layers.

w_new = w_pretrained − small updates
for p in backbone.parameters(): p.requires_grad = False

Data augmentation

Create label-preserving variants of training examples. Cheap regularisation.

x' = T(x), label unchanged
transforms.RandomResizedCrop(224)

Universal approximation

A wide enough network with one hidden layer can approximate any continuous function on a compact set. It says nothing about how easy it is to learn.

f ≈ Σ vᵢ · σ(wᵢ·x + bᵢ)
nn.Sequential(nn.Linear(d, 1024), nn.ReLU(), nn.Linear(1024, 1))

Concept 01

Tokenisation: turning text into numbers

Models cannot read letters, so text is split into tokens, small pieces that map to integer IDs. Whole words would need an enormous vocabulary and could not handle new words. Single characters make sequences too long. Byte-pair encoding (BPE) sits in the middle: start from characters and repeatedly merge the most frequent adjacent pair into a new token.

Common words end up as one token; rare words break into reusable pieces. This is why a model can read a word it has never seen, and why token counts, not word counts, set context limits and prices.

Python · BPE merge loop and a real tokenizer
from collections import Counter

def bpe_merges(words, n_merges):
    seqs = {w: list("▁" + w) for w in set(words)}          # start from characters
    freq = Counter(words)
    merges = []
    for _ in range(n_merges):
        pairs = Counter()
        for w, toks in seqs.items():
            for a, b in zip(toks, toks[1:]):
                pairs[(a, b)] += freq[w]
        if not pairs: break
        (a, b), _ = pairs.most_common(1)[0]
        merges.append((a, b))
        for w, toks in seqs.items():                        # apply the merge everywhere
            out, i = [], 0
            while i < len(toks):
                if i < len(toks) - 1 and (toks[i], toks[i + 1]) == (a, b):
                    out.append(a + b); i += 2
                else:
                    out.append(toks[i]); i += 1
            seqs[w] = out
    return merges

Learner tips

  • Count tokens, not words, when you budget context windows or cost. English averages roughly 1.3 tokens per word, and other languages and code can be much higher.
  • Tokenisation explains odd failures: models struggle to spell words or count letters partly because they see tokens, not characters.
  • Always use the tokenizer that matches the model. IDs from a different vocabulary mean nothing.
Concept 02

Embeddings: meaning as geometry

Each token ID indexes a row of a learned table, giving a vector (hundreds to thousands of numbers). Training pushes tokens used in similar contexts toward similar vectors, so directions in this space come to encode meaning. The classic example is that king − man + woman ≈ queen.

Similarity between vectors is usually measured by cosine similarity. The same idea powers semantic search, recommendation and retrieval-augmented generation.

Python · cosine similarity and nearest neighbours
import numpy as np

def cosine(a, b):
    return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))

def nearest(query, table, words, exclude=()):
    sims = [(cosine(query, v), w) for w, v in zip(words, table) if w not in exclude]
    return max(sims)

Concept 03

Self-attention

Attention lets every token look at every other token and decide how much to listen to each. Each token produces a query (what I am looking for), a key (what I offer) and a value (what I pass on). Scores are query–key dot products, softmax turns them into weights, and the output is the weighted sum of values:

Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V Q = X·W_Q K = X·W_K V = X·W_V

Dividing by √d_k keeps dot products from growing with dimension, which would push softmax into saturated, near one-hot weights with tiny gradients. A causal mask hides future tokens so a language model can only look backwards. Multi-head attention runs several smaller attentions in parallel so different heads can specialise.

Python · scaled dot-product attention and multi-head attention
import math, torch, torch.nn as nn

def attention(q, k, v, causal=True):
    d = q.size(-1)
    scores = q @ k.transpose(-2, -1) / math.sqrt(d)            # (B, heads, T, T)
    if causal:
        T = scores.size(-1)
        mask = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)
        scores = scores.masked_fill(mask, float("-inf"))        # hide the future
    return torch.softmax(scores, dim=-1) @ v

class MultiHead(nn.Module):
    def __init__(self, d=256, heads=8):
        super().__init__()
        self.h, self.qkv, self.o = heads, nn.Linear(d, 3 * d), nn.Linear(d, d)
    def forward(self, x):
        B, T, D = x.shape
        q, k, v = self.qkv(x).view(B, T, 3, self.h, D // self.h).permute(2, 0, 3, 1, 4)
        y = attention(q, k, v).transpose(1, 2).reshape(B, T, D)   # merge the heads
        return self.o(y)

print(MultiHead()(torch.randn(2, 10, 256)).shape)
Concept 04

The transformer architecture in 3D

A decoder-only transformer (the GPT family) is a stack of identical blocks around a residual stream, a running vector for each token that every layer reads from and writes back into.

x₀ = TokenEmbedding(ids) + Position for each block: x ← x + Attention( LayerNorm(x) ) x ← x + MLP( LayerNorm(x) ) MLP = W₂ · GELU(W₁ · x) logits = Unembedding( LayerNorm(x) ) next-token probabilities = softmax(logits)

Attention is the only place tokens exchange information. The MLP processes each token on its own and holds much of the model's stored knowledge. Almost all parameters sit in these two parts.

Python · a minimal GPT-style block and model
import torch, torch.nn as nn

class Block(nn.Module):
    def __init__(self, d=256, heads=8):
        super().__init__()
        self.n1, self.n2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.attn = nn.MultiheadAttention(d, heads, batch_first=True)
        self.mlp = nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))
    def forward(self, x):
        T = x.size(1)
        causal = torch.triu(torch.ones(T, T, dtype=torch.bool, device=x.device), 1)
        h = self.n1(x)
        x = x + self.attn(h, h, h, attn_mask=causal, need_weights=False)[0]   # attention writes to the stream
        return x + self.mlp(self.n2(x))                                       # MLP writes to the stream

class TinyGPT(nn.Module):
    def __init__(self, vocab=1000, d=256, layers=4, ctx=128):
        super().__init__()
        self.tok, self.pos = nn.Embedding(vocab, d), nn.Embedding(ctx, d)
        self.blocks = nn.Sequential(*[Block(d) for _ in range(layers)])
        self.norm, self.head = nn.LayerNorm(d), nn.Linear(d, vocab, bias=False)
    def forward(self, ids):
        x = self.tok(ids) + self.pos(torch.arange(ids.size(1), device=ids.device))
        return self.head(self.norm(self.blocks(x)))          # logits for every position

print(TinyGPT()(torch.randint(0, 1000, (2, 16))).shape)     # (2, 16, 1000)
Concept 05

Decoding: choosing the next token

The model outputs a probability for every token. Greedy decoding always takes the top one, which is repetitive. Sampling draws from the distribution, shaped by three controls:

  • Temperature divides the logits before softmax. Below 1 sharpens, above 1 flattens.
  • Top-k keeps only the k most likely tokens.
  • Top-p (nucleus) keeps the smallest set of tokens whose probabilities add up to p.

Python · temperature, top-k and top-p sampling
import torch

def sample(logits, temperature=1.0, top_k=None, top_p=None):
    logits = logits / max(temperature, 1e-6)
    if top_k:
        kth = torch.topk(logits, top_k).values[-1]
        logits = logits.masked_fill(logits < kth, float("-inf"))
    probs = torch.softmax(logits, dim=-1)
    if top_p:
        p, idx = torch.sort(probs, descending=True)
        cum = p.cumsum(0)
        drop = cum - p > top_p                       # tokens beyond the nucleus
        p[drop] = 0
        probs = torch.zeros_like(probs).scatter(0, idx, p / p.sum())
    return torch.multinomial(probs, 1).item()
Concept 06

Scale, pretraining and compute

Training a language model is next-token prediction on huge text corpora (pretraining). Compute for a dense transformer is about C ≈ 6·N·D floating-point operations, where N is parameters and D is training tokens. The Chinchilla study (Hoffmann et al., 2022) found that for a fixed compute budget, parameters and tokens should grow together, at roughly 20 tokens per parameter. Many modern models train on far more than this to make a smaller model cheaper to run.

After pretraining, models are usually refined with supervised fine-tuning on instruction–answer examples and then preference tuning (RLHF, or simpler methods such as DPO) so answers follow human preferences.

Concept 07

Fine-tuning efficiently with LoRA

Updating every weight of a large model needs optimiser state several times the model's size. LoRA freezes the original weight W and learns a small low-rank update instead:

W' = W + (α / r) · B · A W: d×k (frozen) B: d×r A: r×k r ≪ min(d, k) trainable parameters per matrix = r · (d + k)

QLoRA also stores the frozen weights in 4-bit precision, so large models can be tuned on a single GPU. The adapters are tiny files that can be swapped or merged back into W.

Concept 08

Retrieval-augmented generation

A model's knowledge is frozen at training time and can be wrong. RAG fixes this by fetching relevant text at question time and putting it in the prompt: split documents into chunks, embed them, find the chunks closest to the question, and ask the model to answer using them. It reduces hallucination and lets you cite sources and update knowledge without retraining.

Try it

A working retrieval step

This retrieves from eight tiny notes using TF-IDF, a classic word-weighting method. Real systems use learned embeddings, but the pipeline is identical: score, rank, paste into the prompt.

Python · retrieval with sentence embeddings
import numpy as np
from sentence_transformers import SentenceTransformer

docs = ["LoRA trains small low-rank adapters.", "Diffusion models remove noise step by step."]
enc = SentenceTransformer("all-MiniLM-L6-v2")
D = enc.encode(docs, normalize_embeddings=True)

def retrieve(question, k=1):
    q = enc.encode([question], normalize_embeddings=True)[0]
    top = np.argsort(-(D @ q))[:k]                    # cosine similarity (vectors are normalised)
    return [docs[i] for i in top]

prompt = "Answer using only this context:\n" + "\n".join(retrieve("how are images generated?")) + "\n\nQuestion: ..."

Common traps

  • Bad chunking is the top cause of poor RAG. Chunks that split a thought, or are huge, retrieve badly. Try 200–500 tokens with some overlap.
  • Retrieval can return the wrong text, and the model may still sound sure. Evaluate retrieval (recall@k) separately from generation.
  • Retrieved text can contain instructions. Treat it as untrusted data to avoid prompt injection.

Industry now

  • TF-IDF shows the principle. Production retrieval uses BM25 plus dense embeddings, fused and reranked, with evaluation of recall. The Applied LLMs page has a hands-on comparison.
Concept 09

Small but important concepts

The parts of the LLM stack that people skip and then get bitten by.

Positional encoding

Attention ignores order, so position information is added. The original transformer used fixed sines and cosines.

PE(pos, 2i) = sin(pos / 10000^(2i/d))
PE = np.sin(pos / 10000 ** (2 * i / d))

Rotary embeddings (RoPE)

Rotate query and key vectors by an angle that depends on position, so attention depends on relative distance. Widely used in current models.

q·k depends on (m − n)
apply_rotary_emb(q, k, freqs)

KV cache

When generating, keep each past token's keys and values instead of recomputing them. Memory grows with context length.

bytes = 2 · L · n_kv · d_head · T · bytes_per_value
past_key_values = out.past_key_values

Context window

The most tokens the model can attend to at once. Cost of full attention grows with its square.

attention cost ∝ T²
len(tokenizer(text).input_ids)

FlashAttention

Computes exact attention in tiles that fit fast on-chip memory, avoiding the big T×T matrix in slow memory.

same result, less memory traffic
F.scaled_dot_product_attention(q, k, v, is_causal=True)

Grouped-query attention

Several query heads share one key/value head. Shrinks the KV cache with little quality loss.

n_kv_heads < n_heads
n_kv_heads = 8, n_heads = 32

Pre-norm

Apply LayerNorm before attention and MLP (inside the residual branch). Trains more stably than the original post-norm.

x ← x + F(LN(x))
x = x + self.attn(self.ln(x))

Weight tying

Reuse the embedding matrix as the output projection to save parameters.

logits = h · Eᵀ
self.head.weight = self.tok.weight

Mixture of experts

Many MLP experts, but a router sends each token to only a few. More parameters at similar compute.

y = Σ g_i(x) · Expert_i(x), top-k gates
scores = router(x).topk(2)

Quantisation

Store weights in fewer bits (8 or 4) to cut memory and speed up inference, at some accuracy cost.

w_q = round(w / s), w ≈ s · w_q
load_in_4bit=True

Distillation

Train a small student to match a large teacher's output distribution.

loss = KL(p_teacher ‖ p_student)
F.kl_div(student.log_softmax(-1), teacher.softmax(-1))

Chat template

Chat models expect specially formatted roles and separators. Wrong formatting quietly lowers quality.

<system> … <user> … <assistant>
tokenizer.apply_chat_template(messages)

RLHF and DPO

Tune the model toward answers humans prefer. DPO does it directly from preference pairs without a separate reward model.

max log σ(β(log π(y_w)/π_ref(y_w) − log π(y_l)/π_ref(y_l)))
DPOTrainer(model, ref_model, ...)

Hallucination

The model produces fluent text that is not grounded in facts. Mitigate with retrieval, citations and verification.

P(token | context) is plausibility, not truth
ground the answer in retrieved text

Evaluation

Test on held-out tasks that match your use case, with fixed prompts and many samples. Public benchmarks can be contaminated.

accuracy over N examples ± standard error
lm_eval --model hf --tasks hellaswag

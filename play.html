import torch, math

# 1) Overfit one tiny batch. If the loss will not go to about zero, there is a bug.
xb, yb = next(iter(train_loader))
for step in range(200):
    loss = loss_fn(model(xb), yb)
    opt.zero_grad(); loss.backward(); opt.step()
print("tiny-batch loss:", loss.item())

# 2) Loss at initialisation should be about ln(number of classes) for balanced classification.
print("expected:", math.log(num_classes))

# 3) Look at gradient norms and check for NaNs.
total = torch.sqrt(sum((p.grad ** 2).sum() for p in model.parameters() if p.grad is not None))
print("grad norm:", total.item(), "any NaN:", any(torch.isnan(p).any() for p in model.parameters()))
Concept 02

Find a learning rate: the range test

The learning rate is the setting most worth tuning. The LR range test raises the learning rate exponentially during one short run and plots the loss. Pick a value a bit below where the loss stops falling and before it blows up. Here it runs on the line-fitting problem from the first page.

Python · the range test in PyTorch
import torch

def lr_range_test(model, loader, loss_fn, lr_min=1e-6, lr_max=1.0, steps=100):
    opt = torch.optim.SGD(model.parameters(), lr=lr_min)
    gamma = (lr_max / lr_min) ** (1 / steps)
    lrs, losses, it = [], [], iter(loader)
    for _ in range(steps):
        try: x, y = next(it)
        except StopIteration: it = iter(loader); x, y = next(it)
        loss = loss_fn(model(x), y)
        opt.zero_grad(); loss.backward(); opt.step()
        lrs.append(opt.param_groups[0]["lr"]); losses.append(loss.item())
        if not torch.isfinite(loss): break
        for g in opt.param_groups: g["lr"] *= gamma           # exponential ramp
    return lrs, losses            # plot losses against lrs on a log x-axis
Concept 03

Hyperparameter starting points

Defaults that are reasonable starting points, not laws. Change one thing at a time and log everything.

SettingStarting pointNotes
OptimiserAdamWSGD with momentum 0.9 is a strong alternative for vision models
Learning rate (Adam)1e-3 for small nets, 3e-4 to 1e-4 for transformers, 1e-5 to 5e-5 to fine-tuneSweep on a log scale. Most sensitive setting
Weight decay0.01 to 0.1 (AdamW)Skip for biases and normalisation parameters
Batch size32 to 256, as memory allowsScale learning rate with batch size, and use gradient accumulation to fake larger batches
Warmup1% to 5% of stepsImportant for transformers and large batch sizes
ScheduleCosine or linear decay to near zeroShort runs: one-cycle
Dropout0.1 to 0.3Less when data is plentiful, and often 0 for large pretraining
Gradient clippingMax norm 1.0RNNs, transformers, RL
InitialisationKaiming (ReLU) or Xavier (tanh), library defaults are usually fineZero-init the last layer of residual branches in very deep nets
EpochsUntil validation stops improvingUse early stopping and keep the best checkpoint

Search strategy

  • Random search beats grid search when only a few settings matter, which is common, because it tries more distinct values of each.
  • Tune on a small model or short run first, then scale. Check that the ranking holds.
  • Use several seeds before believing a difference. Run-to-run noise is often as large as the effect.

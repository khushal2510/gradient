01 · Foundations

Classical ML, built up from scratch

Before deep nets and LLMs there is a small set of ideas that still does most of the real-world work: fit a model by minimising a loss, check it on data it has not seen, and keep it as simple as the problem allows. Every demo on this page runs live.

Concept 01

The map: which kind of problem is it?

Almost every ML task falls into one of a few families. Naming the family first tells you which models, losses and metrics make sense.

  • Supervised learning has labelled examples. Predict a number and it is regression; predict a category and it is classification.
  • Unsupervised learning has no labels. You look for structure: clusters, low-dimensional shape, outliers.
  • Self-supervised learning makes its own labels from the data, such as predicting the next word. This is how modern language and vision models are pretrained (see later pages).
  • Reinforcement learning learns from rewards after actions, covered on the RL page.

The workflow barely changes between them: define the target and the metric, split the data, build a dumb baseline, then improve. A model that cannot beat the baseline is telling you something about the data.

Python · a leak-free baseline with scikit-learn
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report

X, y = load_breast_cancer(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=0)

# The pipeline fits the scaler on training data only, so nothing leaks.
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
model.fit(X_tr, y_tr)
print(classification_report(y_te, model.predict(X_te)))

Learner tips

  • Write down the metric before you train anything. Switching metrics after seeing results is a quiet form of cheating.
  • A majority-class or "predict the mean" baseline takes two lines and tells you what "good" means for this dataset.
  • Look at your data first: class balance, missing values, duplicates, and whether the label means what you think it means.
Concept 02

Linear regression and gradient descent

Linear regression fits a line (or plane) to data. The model is ŷ = w·x + b, the loss is the mean squared error, and training means finding the w and b that make that loss small.

loss(w,b) = mean( (w·x + b − y)² ) ∂loss/∂w = 2 · mean( (ŷ − y) · x ) ∂loss/∂b = 2 · mean( ŷ − y ) w ← w − lr · ∂loss/∂w

The gradient points uphill, so each step moves a little downhill. The step size lr (learning rate) is the most important knob in all of deep learning too. Too small and training crawls. Too large and each step overshoots until the loss blows up.

Python · gradient descent versus the closed form
import numpy as np

rng = np.random.default_rng(0)
x = rng.uniform(0, 1, 50)
y = 0.6 * x + 0.25 + rng.normal(0, 0.05, 50)

# 1) gradient descent
w, b, lr = 0.0, 0.0, 0.5
for step in range(500):
    err = (w * x + b) - y
    w -= lr * 2 * np.mean(err * x)
    b -= lr * 2 * np.mean(err)

# 2) closed form (least squares), no learning rate needed
A = np.c_[x, np.ones_like(x)]
w_ls, b_ls = np.linalg.lstsq(A, y, rcond=None)[0]
print(w, b, "vs", w_ls, b_ls)

Learner tips

  • Standardise features (subtract mean, divide by standard deviation). It makes the loss surface rounder, so one learning rate works for every weight.
  • For small linear problems use the closed form or sklearn.linear_model.Ridge. Gradient descent earns its keep when the model has no closed form, which is every neural network.
  • If the loss goes up or turns into nan, lower the learning rate before suspecting anything else.
Concept 03

Logistic regression and measuring a classifier

For classification, logistic regression squashes a linear score through a sigmoid to get a probability, then trains with cross-entropy loss:

p = sigmoid(w·x + b) = 1 / (1 + e^−(w·x + b)) loss = −[ y·log(p) + (1−y)·log(1−p) ]

The model gives scores; you choose a threshold that turns them into decisions. Moving it trades false alarms for misses. The four outcomes (true and false positives and negatives) give the standard metrics:

  • Precision = TP / (TP + FP): of the cases flagged, how many were real.
  • Recall = TP / (TP + FN): of the real cases, how many were found.
  • F1 is their harmonic mean. Accuracy = (TP + TN) / all.

Python · picking a threshold from the precision–recall curve
import numpy as np
from sklearn.metrics import precision_recall_curve, roc_auc_score

scores = model.predict_proba(X_te)[:, 1]
prec, rec, thr = precision_recall_curve(y_te, scores)

# Example policy: the best threshold that still keeps recall at 95% or more
ok = rec[:-1] >= 0.95
best = thr[ok][np.argmax(prec[:-1][ok])]
print("threshold", best, "ROC AUC", roc_auc_score(y_te, scores))

Common traps

  • Accuracy is misleading on imbalanced data. Report precision and recall, or PR-AUC, when positives are rare.
  • Tune the threshold on a validation set, never on the test set.
  • Probabilities from many models are not calibrated. If you need real probabilities, check a calibration plot and consider CalibratedClassifierCV.
Concept 04

k-nearest neighbours and decision boundaries

k-NN has no training step. To classify a point it finds the k closest training points and takes a vote. It is a good way to see what a decision boundary is: the line where the predicted class flips.

Small k gives a jagged boundary that follows every noisy point (low bias, high variance). Large k gives a smooth boundary that may ignore real structure (high bias, low variance). The same trade-off returns in every model you will meet.

Python · choosing k by cross-validation
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import GridSearchCV

pipe = make_pipeline(StandardScaler(), KNeighborsClassifier())
grid = GridSearchCV(pipe, {"kneighborsclassifier__n_neighbors": range(1, 32, 2)}, cv=5)
grid.fit(X_tr, y_tr)
print(grid.best_params_, grid.best_score_)

Learner tips

  • Always scale features first. Distance is dominated by whichever feature has the biggest numbers.
  • k-NN suffers in high dimensions, where all points look about equally far apart. Use PCA or learned embeddings first.
  • It is slow at prediction time on big data. Approximate nearest-neighbour libraries (FAISS, ScaNN) fix that, and the same idea powers vector search for LLM apps.

Industry now

  • Plain kNN rarely ships on large data. Its idea lives on as approximate nearest-neighbour search (HNSW, FAISS, vector databases) behind search, recommendations and RAG.
Concept 05

Decision trees, forests and boosting

A decision tree asks a sequence of yes/no questions about the features ("is x > 0.4?"). At each node it picks the split that makes the child groups purest, measured by Gini impurity 1 − Σ pₖ² or entropy. It repeats until a stopping rule such as maximum depth is hit.

A single deep tree memorises the training data. Two fixes dominate practice:

  • Bagging / random forests train many trees on random resamples and random feature subsets, then average. This cuts variance.
  • Gradient boosting (XGBoost, LightGBM, CatBoost, scikit-learn's HistGradientBoosting) adds small trees one at a time, each fitting the errors of the ensemble so far. This cuts bias, and it is usually the strongest option for tabular data.

Python · forest and boosted trees on tabular data
from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier
from sklearn.inspection import permutation_importance

rf = RandomForestClassifier(n_estimators=300, n_jobs=-1, random_state=0).fit(X_tr, y_tr)
gb = HistGradientBoostingClassifier(learning_rate=0.1, max_depth=4,
                                    early_stopping=True, random_state=0).fit(X_tr, y_tr)
print("forest", rf.score(X_te, y_te), "boosting", gb.score(X_te, y_te))

# Permutation importance is more trustworthy than impurity-based importance
imp = permutation_importance(gb, X_te, y_te, n_repeats=10, random_state=0)
top = imp.importances_mean.argsort()[::-1][:5]
print(top, imp.importances_mean[top])

Learner tips

  • Trees need no feature scaling and handle mixed feature types and missing values (in modern boosting libraries) well.
  • Trees cannot extrapolate. They predict a constant outside the range seen in training, which matters for trending time series.
  • For boosting, use a small learning rate with early stopping on a validation set rather than guessing the number of trees.
Concept 06

Clustering with k-means

k-means groups unlabelled points into k clusters by alternating two steps (Lloyd's algorithm): assign every point to its nearest centre, then update each centre to the mean of its points. Each round lowers the inertia, the total squared distance from points to their centres, until nothing moves.

It always converges, but possibly to a poor local optimum, so the start matters. That is why libraries use k-means++ initialisation and several restarts. You also have to choose k. The elbow plot and the silhouette score are guides, not answers.

from sklearn.cluster import KMeans
from sklearn.decomposition import PCA
from sklearn.metrics import silhouette_score
from sklearn.preprocessing import StandardScaler

Xs = StandardScaler().fit_transform(X)
Z = PCA(n_components=2).fit_transform(Xs)        # 2-D view for plotting

for k in range(2, 7):
    km = KMeans(n_clusters=k, n_init=10, random_state=0).fit(Xs)
    print(k, round(km.inertia_), round(silhouette_score(Xs, km.labels_), 3))

Common traps

  • k-means assumes round, similarly sized clusters. For odd shapes try DBSCAN or a Gaussian mixture model.
  • Features must be scaled, as with k-NN.
  • Clusters are a lens, not truth. Check them against domain knowledge before naming them.

Industry now

  • k-means is common for customer segmentation, vector quantisation and clustering embeddings. For odd cluster shapes and noise, teams often use HDBSCAN. Always scale features and check clusters with a domain expert.
Concept 07

Bias, variance and regularisation

Test error has three parts: bias (the model is too simple to capture the pattern), variance (it is so flexible that it fits noise and changes wildly with a new sample), and irreducible noise. More flexibility lowers bias and raises variance, so test error is U-shaped while training error only falls.

Regularisation adds a penalty on large weights, loss + λ·Σw² (ridge / L2) or λ·Σ|w| (lasso / L1). It lets you keep a flexible model while taming variance.

Python · validation curve for polynomial degree
import numpy as np
from sklearn.linear_model import Ridge
from sklearn.model_selection import validation_curve
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler

rng = np.random.default_rng(0)
x = rng.uniform(0, 1, (60, 1))
y = np.sin(2 * np.pi * x[:, 0]) + rng.normal(0, 0.25, 60)

pipe = make_pipeline(PolynomialFeatures(), StandardScaler(), Ridge(alpha=1e-3))
tr, va = validation_curve(pipe, x, y, param_name="polynomialfeatures__degree",
                          param_range=range(1, 13), cv=5,
                          scoring="neg_mean_squared_error")
print(-va.mean(axis=1).round(3))     # the U-shaped test error

Learner tips

  • Gap between train and validation error large? That is variance: get more data, simplify, regularise or use bagging.
  • Both errors high? That is bias: add features, use a more flexible model or train longer.
  • More data is the one fix that helps variance without hurting bias, so plot a learning curve before collecting more.
Concept 08

Evaluating honestly

A model's score is only as trustworthy as the way it was measured. Use three data roles: train to fit, validation to choose models and hyperparameters, and a test set you touch once at the end. With little data, k-fold cross-validation reuses the data for validation.

Data leakage is when information from outside the training set sneaks in, giving optimistic scores that collapse in production. It is the most common reason a "great" model fails.

LeakExampleFix
Preprocessing before the splitScaling or imputing on the full datasetPut steps in a Pipeline and fit on the training fold only
Duplicate or near-duplicate rowsSame patient in train and testSplit by group (GroupKFold)
Future informationUsing next week's data to predict this weekSplit by time; train on the past, test on the future
Target in disguiseA feature computed from the labelAsk when each feature would be available at prediction time
Python · cross-validation without leakage
from sklearn.model_selection import StratifiedKFold, cross_val_score

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
scores = cross_val_score(model, X, y, cv=cv, scoring="f1")   # model is the Pipeline from above
print(scores.mean().round(3), "+/-", scores.std().round(3))

Learner tips

  • Report a spread (standard deviation across folds), not only a mean. A 0.5-point gain inside the noise is not a gain.
  • Make the validation setup mirror deployment. If the model will see new users, validate on new users.
  • Fix the random seed while comparing models, so differences come from the models.

Concept 10

Explaining a model: permutation importance and SHAP

Teams are often asked why a model made a prediction. Two standard tools:

  • Permutation importance (global): shuffle one feature in held-out data and measure how much the error rises. A feature the model relies on hurts when destroyed.
  • SHAP (per prediction): shares a prediction among the features using Shapley values from game theory, so the contributions add up to the output minus the average output. Fast exact versions exist for tree models.
importance(j) = error( data with feature j shuffled ) − error( data ) SHAP: f(x) = base value + Σⱼ φⱼ(x)

Beware of correlated features. If two features carry the same signal, a model may split its weight between them, and each looks half as important as the signal really is.

Python · permutation importance and SHAP
from sklearn.inspection import permutation_importance
import shap

r = permutation_importance(model, X_test, y_test, n_repeats=10, random_state=0, scoring="neg_mean_squared_error")
for name, m, s in sorted(zip(X.columns, r.importances_mean, r.importances_std), key=lambda t: -t[1]):
    print(f"{name:15s} {m:.4f} ± {s:.4f}")

explainer = shap.TreeExplainer(gbm)              # exact and fast for tree ensembles
sv = explainer(X_test)
shap.plots.beeswarm(sv)                          # global view
shap.plots.waterfall(sv[0])                      # why this one prediction

Explanations in practice

  • Importance describes the model, not causes in the world. A feature can matter to a model without causing the outcome.
  • Compute importance on held-out data. On training data it can reward memorised features.
  • In regulated settings (credit, health) explanations and monitoring are often required, so plan for them early.
Concept 11

Small but important concepts

Short ideas that quietly decide whether a project works. Each has its formula and the one-line call you will actually write.

Standardisation

Centre each feature and give it unit spread so distance and gradient methods treat features fairly.

z = (x − mean) / std
StandardScaler().fit(X_train)

Min–max scaling

Squeeze a feature into a fixed range. Useful for pixels and bounded inputs.

x' = (x − min) / (max − min)
MinMaxScaler()

One-hot encoding

Turn a category into one 0/1 column per value so no false order is implied.

red → [1,0,0], blue → [0,1,0]
OneHotEncoder(handle_unknown='ignore')

Missing values

Impute with the median and add an indicator column, since missingness is often informative.

x_missing = isnan(x)
SimpleImputer(strategy='median', add_indicator=True)

Class weights

Penalise mistakes on the rare class more, as an alternative to resampling.

w_c = N / (K · n_c)
LogisticRegression(class_weight='balanced')

Entropy

How mixed a set of labels is, measured in bits. Trees choose splits that reduce it.

H = − Σ p · log₂(p)
-(p*np.log2(p)).sum()

Bayes' rule

Update a belief with evidence. The basis of Naive Bayes and of probabilistic thinking.

P(A|B) = P(B|A) · P(A) / P(B)
GaussianNB().fit(X, y)

R² score

Share of variance explained. 1 is perfect, 0 matches predicting the mean, and it can go negative.

R² = 1 − SS_res / SS_tot
r2_score(y_true, y_pred)

MAE versus RMSE

MAE is the typical miss. RMSE punishes large misses harder, so it reacts to outliers.

MAE = mean|e| RMSE = √mean(e²)
mean_absolute_error(y, p)

Cosine similarity

Compares direction, not size. The standard way to compare embeddings.

cos = a·b / (‖a‖ ‖b‖)
a @ b / (norm(a) * norm(b))

Log loss

Cross-entropy for probabilities. It punishes confident wrong answers very hard.

−mean( y·log p + (1−y)·log(1−p) )
log_loss(y, p)

Learning curve

Plot score against training set size to learn whether more data would help.

gap(train, val) shrinking → data helps
learning_curve(model, X, y)

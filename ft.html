Concept 01

The pipeline, end to end

Modern language models are built in stages. Each stage changes what data the model sees and what objective it optimises, and each is far cheaper than the one before it. Pretraining gives broad knowledge. Post-training (everything after) shapes behaviour: follow instructions, match human preferences, reason, stay safe.

Concept 02

Pretraining and scaling laws

Pretraining is next-token prediction on a huge text corpus. The loss is cross-entropy on every position at once, so one sequence of length T gives T training signals.

L(θ) = − (1/T) Σₜ log p_θ( xₜ | x₁ … xₜ₋₁ )

Final loss follows a smooth pattern in model size N and training tokens D. The Chinchilla fit is

L(N, D) = E + A / N^α + B / D^β compute ≈ 6 · N · D FLOPs E = 1.69, A = 406.4, B = 410.7, α = 0.34, β = 0.28

For a fixed compute budget C, a model that is too big sees too few tokens, and a model that is too small is starved of capacity. There is a best split in between.

Python · the objective and the budget
import torch, torch.nn.functional as F

def lm_loss(logits, tokens):
    # logits: (B, T, V), tokens: (B, T). Predict token t+1 from positions up to t.
    return F.cross_entropy(logits[:, :-1].reshape(-1, logits.size(-1)),
                           tokens[:, 1:].reshape(-1))

def chinchilla_split(C):
    # roughly 20 tokens per parameter at the compute-optimal point
    N = (C / (6 * 20)) ** 0.5
    return N, 20 * N

Practical notes

  • Compute-optimal is not deployment-optimal. Models meant for heavy use are trained on far more than 20 tokens per parameter, because a smaller model is cheaper to serve forever.
  • Use a learning-rate warmup then cosine decay. Spikes in loss are usually a sign of bad data batches or too high a learning rate.
  • Train in bfloat16 with fp32 optimiser states. Log loss, gradient norm and learning rate at every step.

import hashlib, re

def shingles(text, k=5):
    w = re.findall(r"\w+", text.lower())
    return {" ".join(w[i:i+k]) for i in range(max(1, len(w) - k + 1))}

def minhash(shingle_set, num_perm=64):
    sig = []
    for seed in range(num_perm):
        sig.append(min(int(hashlib.md5(f"{seed}{s}".encode()).hexdigest(), 16) for s in shingle_set))
    return sig

def jaccard_estimate(a, b):
    return sum(x == y for x, y in zip(a, b)) / len(a)   # similarity of the two documents
Concept 04

Supervised fine-tuning (SFT)

A pretrained model continues text. SFT (instruction tuning) trains it on example conversations so it answers instead. Data is (prompt, ideal response) pairs wrapped in a chat template. The key detail is loss masking: you usually compute the loss only on the assistant's tokens, so the model learns to produce answers, not to imitate the user.

import torch

def build_example(tokenizer, messages):
    # messages = [{"role":"user","content":...}, {"role":"assistant","content":...}]
    prompt = tokenizer.apply_chat_template(messages[:-1], tokenize=False, add_generation_prompt=True)
    full   = prompt + messages[-1]["content"] + tokenizer.eos_token       # end-of-sequence is part of the answer
    p_ids  = tokenizer(prompt, add_special_tokens=False)["input_ids"]
    f_ids  = tokenizer(full,   add_special_tokens=False)["input_ids"]
    labels = [-100] * len(p_ids) + f_ids[len(p_ids):]                    # -100 is ignored by cross-entropy
    return {"input_ids": f_ids, "labels": labels}

Common traps

Training for too many epochs on a small SFT set makes the model memorise answers and forget general skills. Watch a held-out set and stop when it stops improving.

Concept 05

Parameter-efficient fine-tuning: LoRA and QLoRA

Full fine-tuning updates every weight and needs memory for gradients and optimiser states. LoRA freezes the weight W and learns a small low-rank update instead:

W' = W + (α / r) · B · A W ∈ ℝ^(d×d), B ∈ ℝ^(d×r), A ∈ ℝ^(r×d), r ≪ d

Trainable parameters per matrix fall from d² to 2·d·r. The bet is that the useful change in weights is low-rank, which is usually true for adapting behaviour. QLoRA also stores the frozen base in 4-bit, so a 7B model fits in a small GPU.

LoRA tips

  • Apply LoRA to all linear layers (attention and MLP), not only q and v. It usually helps.
  • Set α about 2×r as a start. Raise the learning rate compared with full fine-tuning (about 10×).
  • Rank 8 to 32 is enough for most tasks. Raise it only if training loss will not fall.
Concept 06

Why fine-tuning can forget

Picture the weights as a point on a landscape. Pretraining left you in a good region for general ability (the ring). The new task has its own minimum. Moving there lowers the new loss, but moving far from the old region raises the old loss: catastrophic forgetting.

Reducing forgetting

  • Lower the learning rate and train for fewer steps.
  • Mix some general data (replay) into your fine-tuning set.
  • Use LoRA, or merge adapters at a reduced scale.
  • Evaluate on a general benchmark before and after, not only on the new task.
Concept 07

Preference tuning: RLHF and DPO

SFT copies good examples. Often it is easier to say which of two answers is better than to write a perfect one. Preference data is (prompt, chosen, rejected).

RLHF has three steps: train a reward model on preferences, then optimise the policy with RL (usually PPO) to maximise reward while staying near the SFT model through a KL penalty.

Bradley–Terry: P(chosen ≻ rejected) = σ( r(x, y_w) − r(x, y_l) ) RLHF objective: max E[ r(x, y) ] − β · KL( π_θ ‖ π_ref )

DPO skips the reward model and the RL loop. It turns the same objective into a simple classification-style loss on the policy itself:

L_DPO = − log σ( β · [ (log π_θ(y_w) − log π_ref(y_w)) − (log π_θ(y_l) − log π_ref(y_l)) ] )

Python · DPO loss and the TRL trainer
import torch, torch.nn.functional as F

def dpo_loss(pol_w, pol_l, ref_w, ref_l, beta=0.1):
    # each argument: summed log-prob of the full response, shape (B,)
    delta = (pol_w - ref_w) - (pol_l - ref_l)
    return -F.logsigmoid(beta * delta).mean()

Preference-tuning tips

  • DPO needs a very small learning rate (about 5e-7 for full, 5e-6 for LoRA). It is easy to over-train.
  • Start from an SFT model that already writes in the format you want.
  • Watch the chosen log-probability. If it falls a lot, the model is learning to avoid bad answers rather than produce good ones.
  • Variants such as IPO, KTO, SimPO and ORPO change the loss to fix specific issues. Try plain DPO first.
Concept 08

Reward hacking and RL with verifiable rewards

A reward model is only a proxy for what you want. Optimise it hard and the policy finds answers that score high but are not actually good. This is reward hacking (Goodhart's law). A simple way to see it is best-of-n sampling: draw n answers and keep the one with the best proxy score.

When the answer can be checked (maths with a known answer, code with unit tests, formats with a parser), you can skip the learned reward model. RL with verifiable rewards (RLVR) gives reward 1 for a correct result and 0 otherwise. GRPO samples a group of answers per prompt and uses the group itself as the baseline:

Aᵢ = ( rᵢ − mean(r₁…r_G) ) / std(r₁…r_G) no value network needed

import re
from trl import GRPOTrainer, GRPOConfig

def correct_answer(completions, answer, **kw):
    # reward 1.0 if the final boxed number equals the known answer
    out = []
    for c, a in zip(completions, answer):
        m = re.search(r"\\boxed\{([^}]*)\}", c)
        out.append(1.0 if m and m.group(1).strip() == str(a) else 0.0)
    return out

Common traps

Verifiable rewards can still be gamed. A model may learn to print the answer format without reasoning, or to exploit a bug in the checker. Inspect sampled outputs, not only the reward curve.

Concept 09

Making models smaller: quantisation, distillation, merging

Quantisation stores weights in fewer bits. With absmax scaling a weight w becomes an integer q and is mapped back when used:

scale = max|w| / (2^(b−1) − 1) q = round(w / scale) ŵ = q · scale

One large outlier forces a big scale, which wastes resolution for all other weights. The fix is to use a separate scale for each small group of weights.

import torch, torch.nn.functional as F

def quantize_absmax(w, bits=4, group=16):
    w = w.reshape(-1, group)
    scale = w.abs().amax(dim=1, keepdim=True) / (2 ** (bits - 1) - 1)
    q = torch.round(w / scale).clamp(-(2 ** (bits - 1)), 2 ** (bits - 1) - 1)
    return (q * scale).reshape(-1)

def distill_loss(student_logits, teacher_logits, labels, T=2.0, alpha=0.5):
    soft = F.kl_div(F.log_softmax(student_logits / T, -1), F.softmax(teacher_logits / T, -1),
                    reduction="batchmean") * T * T                    # soft targets carry "dark knowledge"
    hard = F.cross_entropy(student_logits, labels)
    return alpha * soft + (1 - alpha) * hard

def merge_models(state_dicts, weights):                               # simple weight averaging ("model soup")
    return {k: sum(w * sd[k] for w, sd in zip(weights, state_dicts)) for k in state_dicts[0]}

Concept 11

Small details that matter

Chat template

Every instruction model expects a specific wrapper of role markers and special tokens. Train and serve with the same template or quality drops.

prompt = tok.apply_chat_template(msgs, tokenize=False, add_generation_prompt=True)
print(prompt)

EOS token

The model must learn to stop. Always append the end-of-sequence token to training responses.

text = answer + tok.eos_token
labels[-1] = tok.eos_token_id

Sequence packing

Concatenate short examples into one long sequence to avoid padding waste. Use attention masks so examples do not see each other.

efficiency = real_tokens / (batch * seq_len)
SFTConfig(packing=True)

Gradient accumulation

Add gradients over several small batches to mimic a large batch with less memory.

effective_batch = micro_batch × accum_steps × n_gpus
loss = loss / accum; loss.backward()

Gradient checkpointing

Recompute activations in the backward pass instead of storing them. About 30% slower, much less memory.

memory ≈ O(√L) activations instead of O(L)
model.gradient_checkpointing_enable()

Mixed precision

Compute in bf16, keep master weights and optimiser states in fp32. bf16 has fp32's range, so it avoids loss scaling.

bf16: 8 exponent bits, 7 mantissa bits
with torch.autocast("cuda", dtype=torch.bfloat16): ...

Rejection sampling

Sample several answers, keep the best by a reward or checker, and fine-tune on them. A simple form of RL.

keep y* = argmax_i r(x, yᵢ)
best = max(samples, key=reward_fn)

Reference model

DPO and RLHF compare against a frozen copy of the starting policy so updates stay close to it.

KL(π_θ ‖ π_ref) = E[ log π_θ − log π_ref ]
ref = copy.deepcopy(model).eval().requires_grad_(False)

Perplexity

Exponent of average token loss. Lower is better. Compare only with the same tokeniser and data.

PPL = exp( L )
ppl = math.exp(loss.item())

Label smoothing

Spread a little target probability over other tokens to reduce over-confidence.

y_smooth = (1−ε) · y + ε / V
F.cross_entropy(logits, y, label_smoothing=0.1)

Learning-rate for fine-tuning

Use 10–100× smaller than pretraining. A too-large rate quickly erases pretrained knowledge.

lr_ft ≈ 1e-5 ... 2e-5 (full)
optimizer = AdamW(model.parameters(), lr=2e-5, weight_decay=0.0)

Evaluation harness

Measure before and after on standard tasks plus your own held-out set. Include a check for general ability loss.

Δ = score_after − score_before
